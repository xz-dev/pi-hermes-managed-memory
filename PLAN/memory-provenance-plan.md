# Task 3.2 — provenance and user edits

Use existing inline Markdown metadata and raw-file hash, not a new manifest/database. Emit entry schema 1 while reading existing unversioned entries; reject unsupported/corrupt metadata, duplicate managed IDs and unreadable files without overwriting. Preserve unknown origins explicitly. Import plain user-authored blocks, including headings and multiline notes, without inventing session IDs or dates. If a managed fact's body no longer matches its stored verbatim source, retain its identity but mark the current fact user-authored/updated unknown and expose the edit diagnostic rather than cite old text. Validate own additions before writing. Inspection lists provenance pointers/times/diagnostics, not raw quote/fact text. Existing isolated Node/SDK tests; mutation/pending/audit/tombstone semantics remain 3.3–3.4.
