## Planned changes

1. Keep original request day/status/usage and raw/prior reports. Add inspected/acknowledged metadata and a separate recovery booking (actual confirmation UTC day, full input/output reservation), without fabricating reported tokens or cost. Booking is idempotent per request under the existing lock and rechecks active ownership. Refuse confirmation when actual UTC day precedes the persisted watermark; retain pause/hold. A booked request has ONE budget debit on its booked day, not booking plus original-day reservation/reported usage. Late telemetry preserves actual/history without an extra debit or automatic refund; either late path re-pauses on overshoot. Admission and overview use the same debit function. Live reservations cannot be acknowledged away.
2. Add a ledger overview shared by commands and persistent display: recent/running results, model/time, UTC-day requests and input/output/cache, held/unknown quantities, known cost subtotal plus unknown-price count, remaining allowances, pause reason and unacknowledged errors. Known late usage does not erase history or silently refund a full confirmed booking; overshoot pauses again.
3. Use public UI status/widget APIs under a separate `hermes-review` key; memory refresh must not erase review failures. Restore from disk on session start/reload and refresh during/after runs and normal foreground turns. Non-TUI modes emit structured terminal/detail output and use the same durable ledger; no raw memory/transcript/credentials in ordinary status.
4. Implement `status|usage|errors|pause|resume|cancel|retry`. Viewing captures exact request IDs/states; confirmation acknowledges only those unchanged records under lock, leaving new/unseen failures blocking. Resume previews unknown booking and remaining budgets before explicit confirmation. Cancel invalidates generation and retains accounting. Retry is a NEW bounded request against the current effective snapshot; bind confirmation to the chosen prior result plus generation/session/project/leaf/snapshot/model/reservation, reject changes and require fresh preview. A confirmed retry bypasses only the selected prior duplicate, never owner/budget/ledger/protocol guards. Without a working public confirmation UI, return structured `confirmation-required`; no booking/resume/dispatch. No hidden request/fallback route or new confirmation framework.
5. Preserve automatic-review-off until later scheduling work. Show off and paused distinctly. Report primary-session usage separately from auxiliary usage, with an explicitly scoped/known subtotal (no claim the extra usage is in Pi native statistics).
